# 分类编码与名称映射说明

适用于 `GET /api/v1/analysis/*`（5003 供数接口）。

## 背景

聚类树会随分析版本重建。新树可能删掉一个第 4 层叶子，只保留它的第 3 层父节点，例如：

```text
旧：S9.M5.3.4
当前：S9.M5.3  「数值推算算错」
```

旧分析结果里仍保存着 `S9.M5.3.4`。接口不会丢掉这条问题，但编码和名称必须按**当前最新树**解释，不能再让调用方自己猜。

## 字段约定

原有字段全部保留，语义不变；新增字段用于当前树映射。

| 字段 | 含义 |
|---|---|
| `problems[].code` | 原始聚类编码，原样保留，便于排查 |
| `problems[].current_code` | 当前树里的最近祖先编码；与 `code` 相同也表示当前树存在 |
| `problems[].legacy_code` | 仅当 `code` 已不在当前树时出现，值等于原 `code` |
| `problems[].label` | 归因条目自己的自由文本标签，**不是**分类名称 |
| `problem_codes` | 原始编码去重列表，原样保留 |
| `problem_current_codes` | 按当前树归一后的编码列表（新增） |
| `problem_label` | `/summary`、`/severity` 问题分组上的当前分类名称（新增） |

叶子分组仍然按原始 `code` 分组，计数口径不变；要看当前名称用 `problem_label`，要看当前编码用 `current_code` / `problem_current_codes`。

## 示例

### 1. `/traces` 或 `/traces/{id}`

```json
{
  "problem_codes": ["S9.M5.3.4"],
  "problem_current_codes": ["S9.M5.3"],
  "problems": [{
    "code": "S9.M5.3.4",
    "current_code": "S9.M5.3",
    "legacy_code": "S9.M5.3.4",
    "label": "增速倍率与利润率差距夸大",
    "severity": "P2"
  }]
}
```

### 2. `/summary` 或 `/severity` 按问题分组

```json
{
  "keys": {"problem": "S9.M5.3.4"},
  "problem_label": "数值推算算错",
  "traces": 73,
  "problems": 73
}
```

`keys.problem` 仍是原始编码，`problem_label` 是当前树名称。

## 筛选

旧编码仍可用于筛选：

```http
GET /api/v1/analysis/summary?dataset=aime_eval&problem=S9.M5.3.4
```

服务端会把它归到当前树最近祖先 `S9.M5.3` 再展开。新代码建议直接传 `current_code` / `problem_current_codes`。

## 版本

- 不要硬编码 `4.3.0` 之类的版本号。以响应 `meta.taxonomy_version` 为准。
- `/taxonomy?kind=problem` 返回当前树；旧版本的树不会保留，传已不存在的 `taxonomy_version` 会返回 404。
- 展示分类名称时优先用本条数据上的 `problem_label` 或 `current_code`，不要只拿原始 `code` 去当前树里直接查。
