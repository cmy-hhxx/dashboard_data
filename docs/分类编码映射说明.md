# 分类编码与名称映射说明

适用于 `GET /api/v1/analysis/*`（5003 供数接口）。

## 一句话

分类树升版后，旧编码仍会返回；展示名称请用新增的 `current_code` / `problem_label`，不要直接拿原始 `code` 去当前树里查。

示例：

```text
原始编码：S9.M5.3.4
当前编码：S9.M5.3
当前名称：数值推算算错
```

## 新增字段

| 位置 | 字段 | 说明 |
|---|---|---|
| `problems[]` | `current_code` | 当前树里的最近祖先编码 |
| `problems[]` | `legacy_code` | 仅旧编码出现，值等于原 `code` |
| `problems[]` | `label` | 归因条目自己的文本标签，**不是分类名称** |
| 顶层 | `problem_current_codes` | 当前树编码列表 |
| `/summary`、`/severity` 分组 | `problem_label` | 当前分类名称；未聚类分组（`keys.problem=null`）固定为 `"未聚类"` |

原有 `code`、`problem_codes`、分组 key、计数全部保留，不影响现有报表。

> `code=null` 不是“其他”，也不是异常：表示聚类流水线尚未覆盖该问题。它仍计入 `problems` 和 P0–P4。
> 聚类覆盖上限见响应 `meta.cluster_through`；当天数据通常还没被覆盖。

## 返回示例

### `/traces` 或 `/traces/{id}`

```json
{
  "problem_codes": ["S9.M5.3.4"],
  "problem_current_codes": ["S9.M5.3"],
  "problems": [{
    "code": "S9.M5.3.4",
    "current_code": "S9.M5.3",
    "legacy_code": "S9.M5.3.4",
    "label": "增速倍率与利润率差距夸大",
    "severity": "P2"
  }]
}
```

### `/summary` 或 `/severity` 按问题分组

```json
{
  "keys": {"problem": "S9.M5.3.4"},
  "problem_label": "数值推算算错",
  "traces": 73,
  "problems": 73
}
```

## 对接建议

1. **展示名称**：优先用 `problem_label`；没有分组名称时用 `current_code` 去 `/taxonomy` 当前树取 `label`。
2. **筛选**：旧编码仍可用，服务端会自动归到当前树；新代码建议传 `current_code`。
3. **版本**：不要硬编码 `4.3.0` 等版本，使用响应里的 `meta.taxonomy_version`。
4. **兼容**：本次只加字段，不改已有字段和计数；无需迁移历史数据。
