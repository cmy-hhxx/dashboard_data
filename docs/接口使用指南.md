## 2. 核心概念与口径

- **trace**：单轮对话，`trace_id` 取 `turns[].meta.trace_id`（非 session_id，跨模型/重跑不唯一）。
- **problem**：归因问题条目，带 `label`、`severity`（`P0`–`P4`，P0 最重，P4 为过程已恢复提示级）、`component`、`evidence`；无标准答案，`is_correct` 恒 `null`。
- **problem code**：聚类编码（如 `S9.M5.1`）。`code=null` 表示**未聚类**（不是“其他”或故障），照常计入 `problems` 与 P0–P4，按 `problem` 分组落 `{"problem": null, "problem_label": "未聚类"}`。
- **intent**：金融意图分类体系 v1.9（`2026-11`，19 一级 `FIN-L1-*` / 123 二级 `FIN-L2-*`）。AIME 优先按 `trace_id` 关联 `category_meta.json`，兜底归因 `task/task_category`；旧体系标签置 `null`。问财 RSI 当前通常为 `null`。
- **`day` 时区**：按 `meta.timestamp` 换算业务日——AIME 为 `America/New_York`，问财为 `Asia/Shanghai`；不要用归因批次文件名日期代替 `day`。
- **测试账号不供数**：仅纯 ASCII 数字且 ≤ 10 位为真实用户，其余整条不进入 5002/5003（规则见 `<datasets>/user_rules.json`）。
- **时效**：时间统一 UTC 存储；5003 延迟 ≤ 1h，5001 看板 ≤ 10m，5002 索引缓存 ≤ 2m。

|---|---|---|---|
| AIME | `aime_eval` | `AIME-Atlas_expert`、`aime-fast-new_fast` | `prelaunch`（日常）、`feedback`（流失） |
| 问财 | `wencai_eval` | `b_expert`、`b_fast` | cohort：`新用户W1-3`、`新用户W4以上`、`老用户W1-3`、`老用户W4以上` |

## 3. 5003 供数接口（`/api/v1/analysis`）

`GET`/`POST` 同语义（`/traces/batch` 仅 POST）；`dataset` 必填；200 包络 `{request_id, schema_version:"2.0", data, meta}`；`cursor` 30 分钟过期（410）。

| 端点 | 作用 | 关键参数与约束 |
|---|---|---|
| `GET /taxonomy` | 分类树与严重度定义 | `kind=intent\|problem\|severity`；`problem` 按 `app_version` 选树 |
| `GET\|POST /severity` | P0–P4 条目数与 trace 数 | `group_by`（0–2 维，可省略），`limit ≤ 1000` |
| `GET\|POST /summary` | 多维聚合 | `group_by`（1–2 维必填：`intent/problem/day/user/app_version/source`），`level=top\|leaf\|children`，`limit ≤ 1000` |
| `GET\|POST /traces` | trace 列表 | `severity`、`problem`、`intent`、`user_ids`(≤5000)、`q`(≤200)；`page_size ≤ 100`（`ids_only=true` ≤5000） |
| `GET\|POST /users` | 按用户聚合（Px → user_id） | 返回每人 `analyzed` 分母、P0–P4 明细、`sample_trace_id`；`limit ≤ 1000` |
| `POST /traces/batch` | 批量摘要（≤1000） | 按请求顺序返回；未分析标 `status:"not_analyzed"` |
| `GET /traces/{id}` | 单条详情 | **`day` 必填**；返回原始输入、完整 `analysis.problems[]`、`data.file`、`history[]` |
| `GET\|POST /changes` | **增量同步**（推荐替代全量导出） | 首次不传 `since` 得全量 + `next_since`；后续传 `since` 只拉 `upsert/delete`；`page_size ≤ 1000` |
| `GET /docs[/{name}]` | 在线 Markdown 文档 | 无需仓库即可读取 `接入说明`、`incremental` |

- **编码升版**：展示名称优先读 `problem_label` / `current_code`（旧编码保留在 `legacy_code`），版本看 `meta.taxonomy_versions`。
- **增量落库**：禁止按时间戳重拉；按三元组主键 `(trace_id, day, app_version)` 幂等 upsert，先落库后存 `next_since`；遇 `409 SYNC_RESET` 清空 `since` 重跑一次全量。

## 4. 5002 页面接口（联动跳转）

```text
/?product=<aime|wencai>&case=<split>%7C<model>%7C<session_id>&trace=<trace_id>
```

- AIME 映射：`source=prelaunch→daily`、`feedback→lost`；`app_version` 后缀 `_expert→aime_expert`、`_fast→aime_fast`。
- 问财映射：`split=daily`，`model=b_expert|b_fast`。
- 也支持 `?product=...&slug=<10位hex>`；附加展示页：`/matrix/?matrix=1`（聚类矩阵）、`/compare/?compare=1&...`（版本对比）。
- 召回索引 `/samples-<product>.json` 不含问题标签 `lb`，需与 `/labels-<product>.json` 按行号配对。

## 5. 常见坑速查

1. `/summary` 必须带 `group_by`；只取总量用 `/severity` 的 `total`。
2. `cluster_through` 是批次日期，不可与业务日 `day` 比较；单条是否已聚类看 `code != null`。
3. `trace_id` 不全局唯一：查详情必带 `day`，导出按 `(trace_id, day, app_version)` 去重。
4. 跨轮（session 级）问题挂会话最后一轮（`session_level: true`），只计一次。
5. 5003 与看板存在快照时间差，刚入库的 trace 打开 5002 可能短暂提示未找到。
