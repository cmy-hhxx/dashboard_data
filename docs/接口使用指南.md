## 1. 两个接口

| 接口 | 作用 |
|---|---|
| **5003 供数** | 按条件查 trace、问题条目、P0–P4、按维度聚合 |
| **5002 页面** | 把一条 trace 打开成对话详情页，并定位到会话中的那一轮 |

```text
5003  $API/traces → trace_id / session_id
        │  case = split|model|session_id
        ▼
5002  $PAGE/?product=aime&case=…&trace=<trace_id>
```

## 2. 核心概念与统一口径

- **trace**：一条单轮对话；`trace_id` 取自归因的 `turns[].meta.trace_id`，不是外层 session id。
  同一 session 多轮各算一条 trace。
- **problem**：归因出的问题条目，带 `label`、`severity`(P0–P4)、`component`、`evidence`。
  没有 `is_error` / `is_correct`（无标准答案，`is_correct` 恒 `null`）。
- **intent**：采用金融意图分类体系 v1.9（版本 `2026-11`，19 个一级类 `FIN-L1-01`–`FIN-L1-19`、123 个二级类 `FIN-L2-001`–`FIN-L2-123`）；入库依次取 `turns[].meta.task`/`task_category` 兜底 `session_meta.task_category`/`subtask_category`。`/traces`、`/changes`、`/traces/{id}` 均返回 `intent_code`、`task`、`subtask`（历史旧标签或表外新增标签仍保留 `task`/`subtask` 原文，`intent_code` 为 `null`）。
- **problem code**：聚类编码（如 `S9.M5.1`）。只有被聚类的问题才有；
  `code=null` / `problem_codes=[]` 表示**未聚类**，**不是“其他”、不是解析失败、不是上游故障**。
- **`day` 按业务时区**从每条 trace 的 `meta.timestamp` 换算：AIME 是美东
  （`America/New_York`，含夏令时），问财是国内业务（`Asia/Shanghai`）。
  归因文件按评测批次命名，但**一个文件可能包含多天 / 重跑记录**，不能用文件名日期代替 `day`；
  来源批次文件见 `/traces/{id}` 的 `data.file`。
- **未聚类问题照常计数**：计入 `problems` 和 P0–P4；按 `problem` 分组时进 `{"problem": null}` 组，
  该组的 `problem_label` 固定为 `"未聚类"`。
- **聚类覆盖滞后**：`meta.cluster_through` 是聚类覆盖到的**批次日期**，不是 `day`。
  单条是否已聚类看 `code`；整体覆盖看 `meta.cluster_updated_at`，或等下一轮聚类。
  不要用 `day <= cluster_through` 判断。
- **测试账号不供数**：真实 userid = 纯数字且 ≤10 位（业务方 2026-11-17 口径）；英文名 / 内部号 /
  ≥11 位数字都算测试账号，整条 trace 不进入任何接口。名单与位数上限在 `<datasets>/user_rules.json`，看板 `ut` 同一口径。
- 时间统一 UTC；数据延迟 ≈ 落盘 + 最多 1 小时。

| 部署 | `dataset` | `app_version` | `source` |
|---|---|---|---|
| AIME | `aime_eval` | `AIME-Atlas_expert`、`aime-fast-new_fast` | `prelaunch`（日常评测）、`feedback`（流失用户） |
| 问财 | `wencai_eval` | `b_expert`、`b_fast`（RSI 模型目录名） | 用户分层 cohort：`新用户W1-3`、`新用户W4以上`、`老用户W1-3`、`老用户W4以上` |

问财的 `source` 直接取 RSI 归因目录里的 cohort（与记录里的 `session_meta.user_type` 一致）；
按 `source` 分组即可做分层的 P0–P4 与问题统计。

## 3. 5003 供数接口

### 通用约定

- `GET` / `POST` 同语义；`/traces/batch` 只收 POST。
- `dataset` 必填，且必须是该实例服务的那份数据：弗吉尼亚 `aime_eval`、乌兰 `wencai_eval`；
  传另一个会返回 422 `UNKNOWN_VALUE`。
- 200 响应：`{request_id, schema_version:"2.0", data, meta}`；`meta.filters` 回显生效条件。
- 翻页用 `cursor`（30 分钟过期返回 410）。`/traces` 的 `page_size` ≤100（`ids_only=true` 时 ≤5000）；
  `/summary`、`/severity` 的 `limit` ≤1000；`/changes` 的 `page_size` ≤1000。
- 未知编码 / 严重度返回 422；`user_ids` >5000、`trace_ids` >1000 返回 413。

### 1) P0–P4：`/severity`

```bash
curl -s "$API/severity?dataset=aime_eval"
curl -s "$API/severity?dataset=aime_eval&group_by=app_version"
```

- `severity.Pn.problems`：该等级问题条目数；`severity.Pn.traces`：至少有一条该等级问题的 trace 数。
- `problems` = 各等级之和 + `unlabeled`；`total.analyzed` 是分母。
- `group_by` 支持 0–2 个维度：`intent`、`problem`、`day`、`user`、`app_version`、`source`。

### 2) 维度聚合：`/summary`

```bash
curl -s "$API/summary?dataset=aime_eval&group_by=problem&level=top"
curl -s "$API/summary?dataset=aime_eval&group_by=day"
```

- `level`：`top`（环节）/ `leaf`（最细编码）/ `children`（筛选值的下一层），只作用于 `intent`、`problem`。
- `total.problem_traces`：至少一个问题条目的 trace 数；`problems`：问题条目数。
- 按 `problem` 分组时每个条目只归一组，各组 `problems` 之和 = `total.problems`；`traces` 会跨组重复。
- `analyzed` 是去掉 `problem` / `severity` 筛选、忽略 `problem` 分组维度后的 trace 数。

### 3) 列 trace：`/traces`

```bash
curl -s "$API/traces?dataset=aime_eval&severity=P0&page_size=2"
```

常用筛选：`source`、`start_day`/`end_day`、`intent`、`problem`、`severity`、`app_version`、
`user_ids`、`q`。`total` 恒等于同条件下 `/summary` 的 `traces`。

- `problems[]` 精简为 `{code, current_code, label, severity, component, session_level}`；
  完整 `definition/reason/evidence` 走详情。
- `problem_codes` 是已聚类编码去重结果；`problem_count` = `problems` 长度。
- `ids_only=true` 只返回 trace_id，便于导出；**`trace_id` 不唯一**（跨模型/重跑重复），导出需去重。

### 4) 批量、单条、分类树

```bash
# 批量（≤1000，返回顺序同请求）
curl -s -X POST "$API/traces/batch" -H 'Content-Type: application/json' \
  -d '{"dataset":"aime_eval","trace_ids":["…","…"]}'

# 单条详情（day 必填）
curl -s "$API/traces/<trace_id>?dataset=aime_eval&day=2026-11-11"

# 分类树
curl -s "$API/taxonomy?kind=problem&app_version=AIME-Atlas_expert"
curl -s "$API/taxonomy?kind=severity"
```

- `batch` 对未知/未分析 id 返回 `status:"not_analyzed"`；同 id 多版本会合并。
- 详情返回 `data.file`（来源归因文件）、`analysis.problems[]`（完整字段）、`analysis.history[]`（旧版本）。
- 跨轮（session 级）问题只挂会话最后一轮，`session_level: true`，只计一次。

### 5) 编码升版字段

| 位置 | 字段 | 说明 |
|---|---|---|
| `problems[]` | `current_code` | 当前树里的最近祖先编码 |
| `problems[]` | `legacy_code` | 旧编码才出现，等于原 `code` |
| `problems[]` | `label` | 归因条目文本，不是分类名称 |
| 顶层 | `problem_current_codes` | 当前树编码列表 |
| 分组 | `problem_label` | 当前分类名称；null 组固定 `"未聚类"` |

展示名称优先用 `problem_label` / `current_code`，不要硬编码分类版本；
版本看 `meta.taxonomy_version` / `meta.taxonomy_versions`。

### 6) 增量同步与在线文档

业务方本地已有数据时，**不要按时间重拉**（归因文件会补数/重跑/整份重写，mtime 不可靠）：

```bash
# 首次：不传 since 即全量导出，按 next_cursor 翻页
curl -s "$API/changes?dataset=aime_eval&page_size=500"

# 之后：保存上一轮的 next_since，只拉变化
curl -s "$API/changes?dataset=aime_eval&since=<next_since>"
```

- 主键 `(trace_id, day, app_version)`；`items[]` 与 `/traces` 同构并多一个
  `change:{seq, op, changed_at}`；`deleted[]` 是删除墓碑。
- 先落库、后更新位点；同一 `since` 重放幂等。位点失效（索引重建）返回 409 `SYNC_RESET`，
  从空 `since` 重新全量同步一次。
- 数据更新时间看 `meta.data_updated_at`、`meta.latest_seq`；`/healthz` 有 `latest_seq`。
- 业务方无需仓库即可取文档：`GET /api/v1/analysis/docs`（索引）、
  `GET /api/v1/analysis/docs/incremental`（增量说明 Markdown）。
  完整客户端伪代码见该文档。

## 4. 5002 页面接口

```text
/?product=aime&case=<split>|<model>|<session_id>&trace=<trace_id>
```

- `product`：`aime` / `wencai`；`case`（历史参数名，值为会话键）里的 `|` 要写成 `%7C`。
- `slug`：也可传 10 位 slug，效果同 `case`；`trace` 可选，用于直接选中并滚动到那一轮。
- 两个展示页：`/matrix/?matrix=1`（聚类矩阵）、`/compare/`（A/B 版本对比）。
- 请求另一个产品会 404；页面数据来自 5001 看板快照，索引缓存 120 秒。
- 5003 与看板有快照时间差时，可能提示“没有找到这条 trace”；先确认 `case` 拼写，或去掉 `trace` 看整个会话。

## 5. 常见坑

1. **`/summary` 必须带 `group_by`**；只要总数用 `/severity` 的 `total`。
2. **未聚类不是“其他”**：`code=null` 单独展示“未聚类”，仍计入问题数和 P0–P4。
3. **`day` 是美东日期**，不是批次文件名日期；批次文件可能包含多天记录。
4. **`cluster_through` 是批次日期**，不要和 `day` 直接比较；最新批次里晚到的 trace 会暂时未聚类。
5. **P4 也是问题**：是否当“提示级”由消费方按 `severity` 决定。
6. **`trace_id` 不唯一**：详情带 `day`，导出先去重。
7. **问财与 AIME 分开部署**：问财 5003 在乌兰、AIME 在弗吉尼亚，`dataset` 不能互传；
   问财样本链接从看板「具体数据」地址栏复制，把端口换成 `2833`。
8. **更新时间**：5003 最多 1 小时；5002 索引最多 2 分钟；看板最多 10 分钟。精确判断看
   `meta.data_updated_at`（数据产物时间）与 `meta.latest_seq`（变更流位点）。
9. **增量同步不要用时间戳**：用 `/changes` 的 `since`/`next_since`；`trace_id` 不唯一，
   本地必须按 `(trace_id, day, app_version)` 落库。
