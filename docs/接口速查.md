## 30 秒了解数据模型

- **trace**：一条单轮对话，`trace_id` 来自归因里的 `turns[].meta.trace_id`。
- **problem**：归因出的问题条目，带 `severity`（P0–P4）、`component`、`evidence`；一条 trace 可有多个。
- **problem code**：聚类编码（`S9.M5.1` 这类）；未聚类为 `null`，但**照样计入**问题数和 P0–P4。
- **source ↔ split**：`prelaunch` = 日常（daily），`feedback` = 流失（lost）。
- **更新频率**：5003 每小时重建索引；5002 索引缓存 120 秒；看板 10 分钟重建一次。

## 一、供数接口（5003）

前缀 `/api/v1/analysis`，`dataset` 必填，AIME 固定 `aime_eval`。GET/POST 同语义（`/traces/batch` 只收 POST）。

- 成功：`{request_id, schema_version:"2.0", data, meta}`（`meta.filters` 回显筛选条件）。
- 失败：`{request_id, error:{code, message, details}}`。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/healthz` | 存活 + 索引状态（`traces`、`problems`、`building`、`built_at`） |
| GET | `/severity` | 数 P0–P4（最常用） |
| GET | `/summary` | 按维度聚合，**`group_by` 必填** |
| GET | `/traces` | 列 trace（最常用） |
| POST | `/traces/batch` | 按一批 `trace_id` 取摘要（≤1000） |
| GET | `/traces/<trace_id>` | 单条详情（完整归因 + 证据） |
| GET | `/taxonomy` | 分类树 `kind=intent\|problem\|severity` |

### 1. 数 P0–P4

```bash
curl -s "$API/severity?dataset=aime_eval"
curl -s "$API/severity?dataset=aime_eval&group_by=day"          # 0–2 个维度
curl -s "$API/severity?dataset=aime_eval&severity=P0,P1&group_by=app_version"
```

```text
data.total = {analyzed, traces, problems, unlabeled,
              severity{Pn:{problems, traces}}}
data.groups[]  每行同结构
```

### 2. 聚合

```bash
curl -s "$API/summary?dataset=aime_eval&group_by=problem&level=top"
curl -s "$API/summary?dataset=aime_eval&group_by=day,source&start_day=2026-11-01&end_day=2026-11-05"
```

- `group_by`：`intent` / `problem` / `day` / `user` / `app_version` / `source`（**1–2 个，必填**，漏了报 400“group_by 不能为空”）。
- `level`：`top`（环节，默认）/ `leaf`（最细编码）/ `children`（当前筛选值的下一层），只作用于 `intent`、`problem`。
- 每行：`{keys, analyzed, traces, users, problem_traces, problems}`。
- `analyzed` 是分母（不受 `problem` / `severity` 筛选、忽略 `problem` 分组）；按 `problem` 分组时 `problems` 之和 = 总数，`traces` 会跨组重复。

### 3. 列 trace

```bash
curl -s "$API/traces?dataset=aime_eval&severity=P0&page_size=2"
curl -s "$API/traces?dataset=aime_eval&start_day=2026-11-01&end_day=2026-11-01&ids_only=true&page_size=5000"
```

每项：`trace_id, day, asked_at, source, user_id, session_id, app_version, query_preview, intent_code, problem_count, problem_codes[], problems[{code,label,severity,component,session_level}], analysis_id`。

- `total` = 同条件 `/summary` 的 `traces`；分页用 `next_cursor`（30 分钟过期 → 410）。
- `page_size` 1–100；`ids_only=true` 时 1–5000，只回 `trace_id`（导出用）。
- `total` 是筛选后的 trace 数；`trace_id` 跨模型/重跑会重复，按需去重。

### 4. 批量 / 单条 / 分类树

```bash
curl -s -X POST "$API/traces/batch" -H 'Content-Type: application/json' \
  -d '{"dataset":"aime_eval","trace_ids":["…","…"]}'

curl -s "$API/traces/20003020179350249318800000000003?dataset=aime_eval&day=2026-11-01"
curl -s "$API/taxonomy?kind=problem&app_version=AIME-Atlas_expert"
```

- 详情里 `analysis.problems[]` 是完整条目（`definition/reason/evidence/…`），`analysis.history[]` 是更早分析版本；`day` 用来消歧同 id 多版本（建议必填）。
- batch 未分析/未知 id 返回 `status:"not_analyzed"`。
- 跨轮（session 级）问题只挂在会话**最后一轮**，`session_level:true`，计数只算一次。

### 筛选参数（通用）

`source`（prelaunch/feedback）、`start_day`/`end_day`、`intent`、`problem`、`severity`、`app_version`、`user_ids`、`q`。
GET 多值用逗号，POST 用数组。

### 错误与限制

| 码 | 含义 |
|---|---|
| 400 | 参数错误（如 summary 缺 `group_by`、`page_size` 越界） |
| 410 | cursor 过期（30 分钟），从第一页重来 |
| 413 | `user_ids` > 5000 或 `trace_ids` > 1000 |
| 422 | 未知编码/严重度/维度取值（`details.allowed` 给出合法值） |
| 404 | trace/day 不存在 |

## 二、页面接口（5002）

### 页面 URL

```text
/?product=aime&case=daily%7Caime_expert%7Cthread_9f…&trace=2000302017935…
```

| 参数 | 说明 |
|---|---|
| `product` | `aime` / `wencai`（各自部署只服务自己产品，另一个 404） |
| `case` | `split\|model\|session_id`，URL 里 `\|` 写成 `%7C` |
| `slug` | 也可传 10 位 slug（索引行的 `s`），效果同 `case` |
| `trace` | 可选，定位到会话里的某一轮；必须和 `case`/`slug` 一起用 |

- 命中 `trace`：选中并滚动到该轮，刷新仍定位；找不到明确报错，不会停在别的轮。
- 不带 `trace`：默认停在最后一轮。

### JSON 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/context?product=aime&case=…`（或 `&slug=…`） | 推荐入口：召回索引行 + taxonomy，`trace` 原样回显 |
| GET | `/samples/<slug>.json` | 单条详情：`input.traces[]`、`attribution.problems[]/turns[]`、`compact`、`evidence[]`（`t/m/b/o` = trace/消息/block/偏移） |
| GET | `/samples-aime.json` | 全量召回索引（AIME ~9MB，建议 `--compressed`） |
| GET | `/healthz` | 存活 + 上游看板探活 |

```bash
curl -sG "$PAGE/api/context" \
  --data-urlencode 'product=aime' \
  --data-urlencode 'case=daily|aime_expert|thread_1f9a49fdcdf041b39e84f12e6a3b147e'
# rows[0].s 就是详情用 slug
curl -s "$PAGE/samples/<slug>.json"
```

- 状态码：200 / 400 参数错误 / 404 样本不存在 / 502 上游看板异常。
- 详情按需生成：首次约 0.5–4 秒，之后走磁盘缓存；索引有 120 秒进程内缓存（看板刚重建最多约 2 分钟才跟上）。

## 三、两个接口怎么配合

```bash
# 1) 5003 找 trace，拿 trace_id / session_id / day
curl -s "$API/traces?dataset=aime_eval&severity=P0&page_size=1" \
  | jq -r '.data.items[0] | [.trace_id,.source,.app_version,.session_id,.day]|@tsv'

# 2) 拼 case：prelaunch→daily（feedback→lost）；*_expert→aime_expert，*_fast→aime_fast
#    case = daily|aime_expert|thread_…

# 3) 5002 打开该轮
open "$PAGE/?product=aime&case=daily%7Caime_expert%7Cthread_…&trace=2000302017935…"
```

## 四、常见坑

1. **`/summary` 必须带 `group_by`**；只要总数用 `/severity` 的 `total`。
2. **`trace_id` 不唯一**：跨模型/重跑会重复，详情带 `day`，导出先去重。
3. **未聚类问题 `code=null`**：不算进 `problem_codes`/编码分组，但照样计入 `problems` 和 P0–P4。
4. **P4 也是问题**：是否当“提示级”由消费方按 `severity` 决定；没有 `is_error`/`is_correct`（无标准答案，恒 `null`）。
5. **数据延迟**：5003 最多 1 小时、5002 索引最多 2 分钟、看板最多 10 分钟；刚追加数据后查不到先等重建，别当成故障。
6. **问财没有 5003**：问财的样本链接从看板「具体数据」地址栏复制，把端口换成 `2833` 即可。
