# 数据拉取同事接口契约（TraceCollectorAdapter）

本服务将“把测试问句交给数据拉取系统、收集返回 trace”抽象为可插拔的 `TraceCollectorAdapter`，支持 **共享目录投递（`file_drop`）** 与 **HTTP 异步派单 + 流式回推（`http`）** 两种生产模式（以及 `mock` 联调模式）。

---

## 1. 我方准备并下发的两份问句 JSONL

任务启动抽题后，我方会在该轮次的 `98_service/dispatch/` 下产出：
- `before_questions.jsonl`（发版前 Agent 待测问句）
- `after_questions.jsonl`（改版后 Agent 待测问句）
- `DISPATCH_MANIFEST.json`（含文件路径、目标回传目录、HTTP 回调路径清单）
- （可选配置 `INTERNAL_EVAL_DISPATCH_SPLIT=by_turn|both` 时，额外产出 `single_turn.jsonl` 与 `multi_turn.jsonl`）

每行 JSON 格式如下：

```json
{
  "run_id": "run_20261124_123000_a1b2c3",
  "version": "1124",
  "side": "after",
  "agent": {"name": "aime-v20261124-rc1"},
  "model": "aime_expert",
  "case_key": "eq_00001",
  "eq_index": 1,
  "case_id": "run_20261124_123000_a1b2c3_after_eq_00001",
  "source_trace_id": "20003020179399888704300000000276",
  "source_session_id": "thread_4fe164f3ea274a0983af85e8ffb3a1c5",
  "question": "How do I get them to do it all in one payment",
  "turn": "multi",
  "session_round": 11,
  "history_messages": [
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."}
  ]
}
```

> **配对铁律**：回传的每条 trace 请务必保留 `case_key`（如 `"eq_00001"`）或保留 `meta.case_id` 末尾的 `_eq_00001`，用于将 `before` 与 `after` 精准同题配对。

## 2. 回传方式 A：HTTP 流式回推（推荐，边拉边评边聚）

每跑完 1 条或一小批 trace，立即回调：

```bash
POST /api/v1/internal-eval/runs/<run_id>/ingest
Content-Type: application/json
```

```json
{
  "side": "after",
  "traces": [
    {
      "case_key": "eq_00001",
      "trace_id": "new_trace_id_001",
      "session_id": "new_session_id_001",
      "request_time": "2026-11-24T12:35:00Z",
      "meta": {
        "trace_id": "new_trace_id_001",
        "session_id": "new_session_id_001",
        "case_id": "run_20261124_123000_a1b2c3_after_eq_00001",
        "question": "How do I get them to do it all in one payment"
      },
      "messages": [
        {"role": "user", "type": "user_question", "content": "..."},
        {"role": "assistant", "type": "final_answer", "content": "..."}
      ]
    }
  ]
}
```

单题拉取失败或整边拉取结束时，回调：

```bash
POST /api/v1/internal-eval/runs/<run_id>/collector-events
Content-Type: application/json
```

```json
// 单题失败
{"side": "after", "event_type": "case_failed", "case_key": "eq_00042", "error_code": "AGENT_TIMEOUT", "error_message": "Agent 响应超时"}

// 整边完成（completed / partial / failed）
{"side": "after", "event_type": "completed", "total_sent": 999}
```

## 3. 回传方式 B：共享目录文件投递（无需 HTTP 回调）

在弗吉尼亚同盘 `/mnt/aime_eval_ssd` 上，拉数程序也可以直接持续追加写入：
- `<round_dir>/98_service/raw_traces/before/*.jsonl`
- `<round_dir>/98_service/raw_traces/after/*.jsonl`

服务后台 tailer 会以 2 秒粒度增量读取新写入的完整行并立刻送入清洗 → 评测 → 聚类；整边写完后在对应目录下创建一个空文件 `_DONE` 即可触发收尾。

---

## 4. 派单协议（`INTERNAL_EVAL_COLLECTOR_MODE=http`）

当拉数同事提供 HTTP 派单端点 `INTERNAL_EVAL_COLLECTOR_BASE_URL` 后，我方会在任务进入 `dispatching` 阶段时自动发起：

```http
POST {INTERNAL_EVAL_COLLECTOR_BASE_URL}/submit
Content-Type: application/json
```

请求体包含 `run_id`、`version`、`model`、`tier`、`sides`、`before_agent`、`after_agent`、`dispatch_files`（两份 JSONL 绝对路径）、`raw_trace_drop_dirs` 与我方 `ingest_path` / `events_path` 回调路径。后续同事接口字段如有调整，只需修改 `internal_eval/collectors.py` 中 `HttpCollectorAdapter` 一处，主流程零改动。
