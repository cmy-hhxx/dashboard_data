# 数据拉取同事接口契约（TraceCollectorAdapter）

本服务将“派发测试问句并收集返回 trace”抽象为 `TraceCollectorAdapter`，支持 `task_manager`（直连 TaskManager）、`file_drop`（共享目录投递）、`http`（异步 HTTP 派单）与 `mock`（联调）。

## 0. TaskManager 对接现状与已知缺口（`INTERNAL_EVAL_COLLECTOR_MODE=task_manager`）

> **⚠️ 已知数据口径缺口（当前阻塞正式上线）**
> - TaskManager（`http://10.217.216.85:8888/api/v1/task`）负责**触发推理并记录会话索引**（`GET /tasks/{id}/cases` 返回各 step 的 `session_id`/`trace_id`）。
> - 其 `GET /tasks/{id}/judge/{key}/download` 仅为摘要字段（`chain`/`text_answer`），**不含完整异步 Litefusion 数据，不符合标准 `eval_harness` 评测输入口径**。
> - **现状与切换点**：`TaskManagerCollectorAdapter` 已跑通 4 步调度闭环（分批 ≤100 建集 `case_id=<run_id>_<case_key>` → 双边合并建任务与启动 → 轮询取数 → `retry-recall`/`fill_missing`/`reset_failed` 自动恢复与取消透传，状态持久化于 `98_service/dispatch/TASK_MANAGER_STATE.json`）。待内部异步 Litefusion 拉数就绪后，只需将 `collectors.py` 第 3 步的 `judge/download` 替换为按 `(session_id, trace_id)` 异步等待并拉取标准 Litefusion trace，其余主流程零改动。

## 1. 下发问句 JSONL 格式

抽题后在 `<round_dir>/98_service/dispatch/` 产出 `before_questions.jsonl`、`after_questions.jsonl` 与 `DISPATCH_MANIFEST.json`（可选 `INTERNAL_EVAL_DISPATCH_SPLIT=by_turn|both` 另出单/多轮文件）。每行示例：

```json
{
  "run_id": "run_20261124_123000_a1b2c3", "version": "1124", "side": "after",
  "agent": {"name": "aime-v20261124-rc1"}, "model": "aime_expert",
  "case_key": "eq_00001", "eq_index": 1,
  "case_id": "run_20261124_123000_a1b2c3_after_eq_00001",
  "source_trace_id": "20003020179399888704300000000276",
  "source_session_id": "thread_4fe164f3ea274a0983af85e8ffb3a1c5",
  "question": "...", "turn": "multi", "session_round": 11,
  "history_messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]
}
```

> **配对铁律**：回传 trace 必须保留 `case_key`（如 `eq_00001`）或 `meta.case_id` 末尾 `_eq_00001`，确保 `before`/`after` 精准同题配对。

## 2. 回传方式 A：HTTP 流式回推（推荐，边拉边评边聚）

```http
POST /api/v1/internal-eval/runs/<run_id>/ingest
Content-Type: application/json
```

```json
{
  "side": "after",
  "traces": [{
    "case_key": "eq_00001", "trace_id": "new_trace_001", "session_id": "new_sess_001",
    "request_time": "2026-11-24T12:35:00Z",
    "meta": {"trace_id": "new_trace_001", "session_id": "new_sess_001",
             "case_id": "run_20261124_123000_a1b2c3_after_eq_00001", "question": "..."},
    "messages": [{"role": "user", "type": "user_question", "content": "..."},
                 {"role": "assistant", "type": "final_answer", "content": "..."}]
  }]
}
```

单题失败或整边结束时回调 `POST /api/v1/internal-eval/runs/<run_id>/collector-events`：

```json
{"side": "after", "event_type": "case_failed", "case_key": "eq_00042", "error_code": "AGENT_TIMEOUT", "error_message": "超时"}
{"side": "after", "event_type": "completed", "total_sent": 999}
```

## 3. 回传方式 B：共享目录投递（`file_drop`）

同盘追加写入 `<round_dir>/98_service/raw_traces/{before,after}/*.jsonl`，后台 tailer 每 2 秒增量消费完整行并立即送入清洗 → 评测 → 聚类；整边写完后在对应目录创建空文件 `_DONE` 触发收尾。

## 4. 自定义 HTTP 派单（`INTERNAL_EVAL_COLLECTOR_MODE=http`）

进入 `dispatching` 时服务向 `POST {INTERNAL_EVAL_COLLECTOR_BASE_URL}/submit` 推送 JSON，含 `run_id`、`version`、`model`、`tier`、`sides`、`before_agent`、`after_agent`、`dispatch_files`、`raw_trace_drop_dirs` 及 `ingest_path` / `events_path` 回调路径。字段差异仅需改 `internal_eval/collectors.py` 的 `HttpCollectorAdapter`。
