# 内部评测与聚类服务接入说明

挂载于弗吉尼亚 `5003` 端口，提供**发版前 vs 改版后 Agent** 全自动抽题、拉数、归因评测与流式增量聚类。

- **服务前缀**：`/api/v1/internal-eval`（对外 `http://10.217.219.2:2477`、集群内 `http://interactive-s3ynzadcvm9c:5003`、本机 `127.0.0.1:5003`）
- **响应包络**：2xx 为 `{request_id, schema_version:"1.0", data, meta}`；错误为 `{request_id, error:{code, message, details}}`。
- **鉴权与配置**：`GET` 内网开放；若配置 `INTERNAL_EVAL_API_TOKEN`，则所有 `POST` 须带 `Authorization: Bearer <token>` 或 `X-API-Key: <token>`。评测/聚类模型与网关由服务端收敛，调用方无需传密钥。
- **在线文档**：`GET /docs`、`GET /docs/接入说明`、`GET /docs/拉数同事接口契约`、`GET /docs/状态机与可视化字段`。

> **TaskManager 自动化闭环**：默认复制模板 `2740e85cb7b34909` 创建 `AIME_RSI_ABTEST_{YYYYMMDD-HHMMSS}`（不设 `limit`），并在 `ab_test/version_<YYYYMMDD>_aime_<model>/<task_id>/` 建目录等待数据侧写入加工后 `{step}.jsonl`（不消费 `raw/` 与 `judge_data`）；默认每 15 分钟巡检补缺重试，收尾运行 `human_read_eval` 生成人话归因（见《拉数同事接口契约》§0）。

## 1. 发起评测任务（`POST /runs`）

```bash
curl -s -X POST "http://10.217.219.2:2477/api/v1/internal-eval/runs" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "1124", "tier": 1000, "model": "aime_expert",
    "before_agent": {"name": "aime-online", "is_pre": false},
    "after_agent": {"name": "aime-pre", "is_pre": true, "agent_id": "analyst-pre"},
    "task_manager": {"concurrency_limit": 10},
    "idempotency_key": "release-1124-expert-1000"
  }'
```

| 参数 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `tier` | 是 | — | 题量档位：`500` / `1000` / `5000` / `10000`（取自 `3_dynamic_bench/<model>/tier_<tier>.jsonl`） |
| `before_agent` / `after_agent` | 是 | — | Agent 标识（字符串或对象；`task_manager` 模式支持附带 step 覆盖项如 `fetcher`/`is_pre`/`mode`/`agent_id`/`lumi_profile_id` 等）；`before_mode=historical` 时可省 `before_agent` |
| `task_manager` | 否 | `{}` | 任务级参数：`template_task_id`（默认 `2740e85cb7b34909`）、`concurrency_limit`、`recovery_interval_sec`（默认 `900`）、`drop_wait_timeout_sec`（默认 `3600`）、`judge_source`（默认 `drop_dir`） |
| `version` / `model` | 否 | `MMDD` / `aime_expert` | 日期版本（严格 `YYYYMMDD`/`MMDD`）；模型仅 `aime_expert`/`aime_fast`，同日同模型重复返回 `409` |
| `sides` / `before_mode` | 否 | `["before","after"]` / `live` | 单双边范围；`live` 实时重跑或 `historical` 复用基线 |
| `idempotency_key` / `callback_url` | 否 | `null` | 幂等防抖键（重复直接返回原任务 200）；Webhook 在 `first_ready` 与终态触发通知 |

## 2. 进度、版本、失败与事件查询

| 端点 | 用途 |
|---|---|
| `GET /runs/{run_id}` | 全景进度：`status`/`stage`、`progress`（完成率/吞吐/ETA）、`sides_detail.{before,after}` 漏斗与 P0–P4 分布、`latest_seq`、`round_dir_path` |
| `GET /runs?version=1124&limit=20` | 按条件列出任务 |
| `GET /versions` · `GET /versions/{ver}[?run_id=]` | 版本列表与指定版本最新轮次进度 + 前后对比 + 历史轮次 |
| `GET /runs/{run_id}/failures?stage=&side=` | 按阶段（`fetch/prepare/eval/cluster/system`）查失败样本明细 |
| `GET /runs/{run_id}/events?limit=50` | 查询任务执行事件流 |

## 3. 流式结果供数与版本对比

首条 trace 评完并聚类（或无问题判 `GOLD`）即刻进入 `ready` 并递增 `change_seq`，无需等待整轮结束。

- **增量同步（推荐）**：`GET /runs/{run_id}/results/changes?since=0&limit=200` — 保存 `next_since`，后续只拉新增或聚类刷新条目。
- **条件查询明细**：`GET /runs/{run_id}/results?side=after&severity=P0&paired_only=true&limit=50` — 支持 `side`、`severity`（`P0`–`P4`/`GOLD`）、`problem_code`（支持前缀）、`case_key`、`paired_only`、`only_ready`。
- **实时前后对比**：`GET /runs/{run_id}/compare?paired_only=true&top_leaves=30` — 返回 `before/after_summary`、`paired_summary`、`severity_migration_matrix`（6×6）、`leaf_comparison`、`stage_mechanism_matrix` 与 `highlights`。

## 4. 控制与看板互通

```bash
curl -s -X POST ".../runs/<run_id>/cancel"   # 安全中止，保留已就绪结果
curl -s -X POST ".../runs/<run_id>/retry-failed" -H "Content-Type: application/json" -d '{"stages":["eval","cluster"]}'
```

落盘目录 `/mnt/aime_eval_ssd/1_aime/ab_test/version_<YYYYMMDD>_<model>/` 采用统一自包含结构（`bench/bench.jsonl`、`agent_before_opt/`、`agent_after_opt/`、`index_stats/`、隐藏运行目录 `.work/`），5001 看板与 5002 对比页自动识别。
