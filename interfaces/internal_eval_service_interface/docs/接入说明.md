# 内部评测与聚类服务接入说明

本文面向外部业务方，说明如何通过 `5003` 端口触发一次**发版前 Agent vs 改版后 Agent** 的全自动内部评测与聚类流水线、查询实时进度与失败明细，并在首条结果产出后即刻拉取与可视化展示。

## 1. 服务地址与通用约定

- **基础前缀**：`/api/v1/internal-eval`
- **弗吉尼亚生产入口**：
  - 对外：`http://10.217.219.2:2477/api/v1/internal-eval`
  - 集群内跨容器：`http://interactive-s3ynzadcvm9c:5003/api/v1/internal-eval`
  - 同容器：`http://127.0.0.1:5003/api/v1/internal-eval`
- **响应信封**：所有 `2xx` 响应统一为 `{request_id, schema_version: "1.0", data, meta}`；错误响应统一为 `{request_id, error: {code, message, details}}`。
- **鉴权**：读接口（`GET`）内网开放；若服务端开启了 `INTERNAL_EVAL_API_TOKEN`，则所有写接口（`POST`）需带 `Authorization: Bearer <token>` 或 `X-API-Key: <token>`。
- **评测/聚类网关与模型**：全部由服务端收敛配置，调用方无需选择也无需传递模型或密钥。
- **在线文档**：
  - `GET /api/v1/internal-eval/docs`（文档目录）
  - `GET /api/v1/internal-eval/docs/接入说明`
  - `GET /api/v1/internal-eval/docs/拉数同事接口契约`
  - `GET /api/v1/internal-eval/docs/状态机与可视化字段`

## 2. 一键发起内部评测

```bash
curl -s -X POST "http://10.217.219.2:2477/api/v1/internal-eval/runs" \
  -H "Content-Type: application/json" \
  -d '{
    "version": "1124",
    "tier": 1000,
    "model": "aime_expert",
    "before_agent": {"name": "aime-v20261119"},
    "after_agent": {"name": "aime-v20261124-rc1"},
    "idempotency_key": "release-1124-expert-1000"
  }'
```

### 参数说明

| 字段 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `tier` | 是 | — | 评测题量档位：`500`、`1000`、`5000`、`10000`（从 `/mnt/aime_eval_ssd/3_dynamic_bench/<model>/tier_<tier>.jsonl` 取题） |
| `before_agent` | 是（`before_mode=live` 时） | — | 发版前 Agent 标识，可传字符串或 JSON 对象（原样透传给拉数接口） |
| `after_agent` | 是 | — | 改版后 Agent 标识，可传字符串或 JSON 对象（原样透传给拉数接口） |
| `version` | 否 | 当天 `MMDD` | 版本号标识（用于 `ab_test/<n>_version<version>_test/` 落盘及按版本查询）；同版本多次发起自动分配新轮次不覆盖历史 |
| `model` | 否 | `"aime_expert"` | 抽题模型库：`aime_expert` 或 `aime_fast` |
| `sides` | 否 | `["before", "after"]` | 本次评测范围，可单测 `["after"]` 或双边对比 `["before", "after"]` |
| `before_mode` | 否 | `"live"` | `live`（双边均走拉数接口实时重跑）或 `historical`（`before` 直接复用 bench 历史基线） |
| `idempotency_key` | 否 | `null` | 幂等防抖键；重复传入相同键直接返回已创建任务（HTTP `200`） |
| `callback_url` | 否 | `null` | 可选 Webhook 地址；在 `first_ready` 及终态（`succeeded` / `completed_with_errors` / `failed` / `cancelled`）发送异步通知 |

## 3. 实时进度、失败明细与事件时间线

### 3.1 查询任务全景进度

```bash
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>"
```

返回内容包含：
- `status` / `stage`：总体状态与当前阶段；
- `progress`：总完成率、就绪数、失败数、拒绝数、已双边配对数、耗时、吞吐速率（条/分）与预计剩余时间 `eta_seconds`；
- `sides_detail.before` / `sides_detail.after`：各自完整漏斗计数（`total_targets → fetched → cleaned → rejected → evaluating → evaluated → gold_pass → clustered → ready → failed`）、各阶段失败统计、P0–P4 & GOLD 分布；
- `dispatch_files`：生成的待拉数问句 JSONL 路径（默认 `before_questions.jsonl`、`after_questions.jsonl`）；
- `latest_seq`：已就绪结果增量位点；
- `round_dir_path`：落盘在 `/mnt/aime_eval_ssd/1_aime/ab_test/` 下的标准三口径目录。

### 3.2 查询任务列表 & 按版本查询

```bash
# 按条件列出任务
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs?version=1124&limit=20"

# 列出全部已跑版本（用于版本下拉选择器）
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/versions"

# 按版本号查询（默认返回最新一轮进度 + 前后对比 + 历史轮次列表）
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/versions/1124"
# 可传 ?run_id=<run_id> 切换到该版本的指定历史轮次
```

### 3.3 查询失败明细与执行时间线

```bash
# 按阶段（fetch / prepare / eval / cluster / system）与 side 筛选失败样本
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/failures?stage=eval&side=after"

# 查看执行事件流
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/events?limit=50"
```

## 4. 边评边聚、实时拉取结果与版本对比

> 只要有 **1 条** trace 评测并聚类完成（或无问题判 `GOLD`），就会立刻进入 `ready` 态并递增 `change_seq`，无需等待整轮结束。

### 4.1 增量同步已就绪结果（推荐业务方落库/实时刷新使用）

```bash
# 首次从 since=0 开始，保存返回的 next_since，后续只拉新增或聚类刷新过的条目
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/results/changes?since=0&limit=200"
```

### 4.2 条件查询已就绪明细

```bash
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/results?side=after&severity=P0&paired_only=true&limit=50"
```

支持筛选：`side`、`severity`（`P0`–`P4` / `GOLD`）、`problem_code`（支持前缀如 `S9` 或 `S9.M5`）、`case_key`、`paired_only`、`only_ready`（默认 `true`）。

### 4.3 实时发版前后可视化对比

```bash
curl -s "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/compare?paired_only=true&top_leaves=30"
```

一次返回前端看板直接可用的全部对比数据：
- `before_summary` / `after_summary`：各自通过率、P0/P1 占比、平均问题数；
- `paired_summary`：已配对题数、改善/恶化/持平题数、净改善率；
- `severity_comparison` & `severity_migration_matrix`（6×6 严重度迁移矩阵）；
- `leaf_comparison`：Top 问题叶子前后增减榜；
- `stage_mechanism_matrix` & `stage_totals`：环节 × 机制交叉热力图数据；
- `highlights.improved_examples` / `regressed_examples`：典型改善与回退样本列表。

## 5. 任务取消与失败项一键补跑

```bash
# 安全中止运行中任务（已完成的结果保留可查）
curl -s -X POST "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/cancel"

# 对失败/被拒样本一键重跑（可按 stages / sides 过滤）
curl -s -X POST "http://10.217.219.2:2477/api/v1/internal-eval/runs/<run_id>/retry-failed" \
  -H "Content-Type: application/json" \
  -d '{"stages": ["eval", "cluster"]}'
```

## 6. 数据目录与看板互通

每轮任务的数据均分门别类落在 `/mnt/aime_eval_ssd/1_aime/ab_test/<序号>_version<版本>_test/` 下：
- `00_manifest/`：覆盖清单 CSV、`summary.json`、`scope_summary.json`（5001 看板与 5002 对比页自动识别）
- `01_targets/questions.jsonl`：本轮冻结测试题集
- `02_before_release/{inputs,attribution,cluster_tree}/<model>/`：发版前清洗输入、归因输出与聚类树
- `03_after_release_retest/{inputs,attribution,cluster_tree}/<model>/`：改版后清洗输入、归因输出与聚类树
- `05_compare/`：前后对比快照与 CSV 基线表
- `98_service/`：下发给拉数同事的两份 JSONL、原始回传 trace、审计日志、本轮隔离分类法副本
