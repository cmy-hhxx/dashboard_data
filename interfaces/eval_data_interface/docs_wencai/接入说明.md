# 问财 RSI 供数接入说明（v2.0）

服务：`eval_data_interface`，对话分析查询接口的**问财**实现。只读、无认证。
部署在乌兰察布，容器端口 `5003`，接口前缀 `/api/v1/analysis`。一次部署只服务这一份数据：

```text
dataset = wencai_eval
```

健康检查：`GET /healthz`（`ok` / `building` / `dataset` / `traces` / `problems` /
`data_updated_at` / `build`）。对外地址由平台把容器 `5003` 映射到公网端口；容器内 / 集群内用
`http://127.0.0.1:5003`、`http://interactive-i6piqwvlnsr5:5003`。

请求头：`Accept: application/json`；POST 另带 `Content-Type: application/json`。
所有 200 响应统一为 `{request_id, schema_version: "2.0", data, meta}`；`meta` 含
`taxonomy_version`、`taxonomy_versions`、`data_updated_at`、`built_at`、`latest_seq`、
`filters`（实际生效的筛选条件回显）。

## 数据来源与口径

```text
<datasets>/0_wencai/eval_output/2_rsi_eval/<model>/<cohort>/<model>_attribution-<date>.jsonl
<datasets>/0_wencai/eval_output/2_rsi_eval/cluster/<model>/total/{cluster_tree.json,item_index.jsonl}
<datasets>/0_wencai/eval_input/2_rsi_input/<model>/<cohort>/data_<YYYYMMDD>.jsonl
```

| 维度 | 取值 | 来源 |
|---|---|---|
| `app_version` | `b_expert`、`b_fast` | RSI 模型目录名 |
| `source` | 用户分层 cohort：`新用户W1-3`、`新用户W4以上`、`老用户W1-3`、`老用户W4以上` | 归因目录 / `session_meta.user_type` |
| `day` | `YYYY-MM-DD`，**Asia/Shanghai** | `turns[].meta.timestamp`（缺时用批次日期） |
| `problem` | `S9` / `S9.M5` / `S9.M5.1` | 聚类树 `cluster/<model>/total`；未聚类 `code=null` |
| `intent` | 通常为 `null` | 金融意图分类体系 v1.9（`2026-11`，`FIN-L1-01`–`FIN-L1-19` / `FIN-L2-001`–`FIN-L2-123`）；入库取 `turns[].meta.task/task_category`，兜底 `session_meta.task_category/subtask_category`。当前 RSI 归因基本不带这些字段，不要依赖 `intent` 分组 |

- **trace**：一条单轮对话，`trace_id` 取 `turns[].meta.trace_id`；同一 session 多轮各算一条。
- **problem**：`turns[].problem[]` 的一项，带 `label`、`severity`(P0–P4)、`component`、`evidence`。
- **聚类**：只有 `cluster/<model>/total` 的累计树对外；cohort 子集树不单独供数。
  未聚类问题照常计入 `problems` 和 P0–P4，按 `problem` 分组时进 `{"problem": null}` 组。
- **没有 compact**：RSI 流水线不发布 compact；详情只依赖 `2_rsi_input` 的原始输入。
- **测试账号不供数**：真实 userid = 纯数字且 ≤10 位；其余整条 trace 不进入任何接口。
  规则在 `<datasets>/user_rules.json`，与看板 `ut` 同口径。
- 时间统一 UTC 存储；`day` 按北京时间划分。数据延迟 ≈ 落盘 + 最多 1 小时。

## 业务问题 → 用哪个接口

| 想做的事 | 用哪个 |
|---|---|
| 看整体质量、P0–P4 各有多少 | `/severity` |
| 按日期 / cohort / 模型看量级与问题数 | `/summary?group_by=…` |
| 列出命中某类问题的 trace | `/traces?severity=P0&problem=S9.M5.1` |
| 有 Px 问题的用户是谁 | `/users?severity=P0` |
| 某个用户下的 Px trace | `/traces?severity=P0&user_ids=<uid>` |
| 打开某条对话 | `/traces?user_ids=<uid>` → `/traces/{trace_id}?day=…` |
| 本地已有一批 trace_id，只要摘要 | `POST /traces/batch` |
| 增量同步 | `/changes?since=…` |
| 分类体系与 P0–P4 定义 | `/taxonomy?kind=…` |

## 通用筛选参数

`/summary`、`/severity`、`/traces`、`/users` 共用：

| 参数 | 类型 | 语义 |
|---|---|---|
| `dataset` | 必填 | 固定 `wencai_eval`；传 `aime_eval` 返回 422 |
| `source` | 多值 | cohort，例如 `新用户W1-3` |
| `start_day` / `end_day` | `YYYY-MM-DD` | trace 所属日期（北京时间），两端都包含 |
| `problem` | 多值编码 | 命中任一问题编码或其子孙 |
| `severity` | 多值，`P0`–`P4` | 至少命中一个该严重度的问题 |
| `app_version` | 多值 | `b_expert` / `b_fast` |
| `user_ids` | 多值 | 单次最多 5000 |
| `q` | 单值 | 问句包含该子串（不区分大小写），最多 200 字 |

- GET 多值用英文逗号，POST 用 JSON 数组；空字符串视为未提供。
- 不同参数之间是「且」，同参数多值之间是「或」。
- 大类编码（`S9`、`S9.M5`）自动展开到全部子孙；完全未知的编码 / 严重度返回 422。
- `intent` 参数对问财没有意义（所有 trace 的 `intent_code` 都是 `null`）；不要依赖它。

## 1. 分类树

```http
GET /api/v1/analysis/taxonomy?kind=problem&app_version=b_expert
GET /api/v1/analysis/taxonomy?kind=severity
```

`data.nodes[]`：`code`、`label`、`parent_code`、`level`、`order`、`definition`。
`problem` 树来自 RSI 聚类 `total`（版本以响应 `meta.taxonomy_version` 为准，不要硬编码）；
`severity` 固定 P0–P4。

## 2. 聚合 `/summary`

```http
GET /api/v1/analysis/summary?dataset=wencai_eval&group_by=source
GET /api/v1/analysis/summary?dataset=wencai_eval&group_by=day&app_version=b_expert
POST /api/v1/analysis/summary
{"dataset":"wencai_eval","group_by":["source","problem"],"app_version":["b_fast"]}
```

参数：`group_by`（1–2 个：`problem`、`day`、`user`、`app_version`、`source`；`intent` 可用但恒为 `null`）、
`level`（`top`/`leaf`/`children`）、`sort`、`limit`（默认 100，最大 1000）、`cursor`。

- `traces`：满足全部筛选的 trace 数；`users`：去重用户数。
- `problem_traces`：至少有一个问题条目的 trace 数；`problems`：问题条目数。
- `analyzed`：去掉 `problem` / `severity` 筛选、忽略分组键里的 `problem` 维度后的 trace 数（分母）。
- 按 `problem` 分组时每个问题条目只归一组，各组 `problems` 之和 = `total.problems`。

## 3. 严重度 `/severity`

```http
GET /api/v1/analysis/severity?dataset=wencai_eval
GET /api/v1/analysis/severity?dataset=wencai_eval&group_by=source
```

- `severity.Pn.problems`：该等级问题条目数；`severity.Pn.traces`：至少有一个该等级问题的 trace 数。
- `problems` = 各等级之和 + `unlabeled`；一条 trace 可同时出现在多个等级，所以各等级 `traces` 之和可能大于总量。
- 不给 `group_by` 时 `groups` 为 `[]`，只返回 `total`。

## 4. trace 列表 `/traces`

```http
GET /api/v1/analysis/traces?dataset=wencai_eval&severity=P0&page_size=2
GET /api/v1/analysis/traces?dataset=wencai_eval&source=新用户W1-3&app_version=b_expert
```

参数：通用筛选 + `page_size`（默认 20，最大 100；`ids_only=true` 时最大 5000）、`cursor`、`ids_only`。
排序固定 `(asked_at DESC, trace_id DESC)`。

`items[]` 关键字段：`trace_id`、`day`、`asked_at`、`source`（cohort）、`user_id`、`session_id`、
`app_version`、`query_preview`、`problem_count`、`problem_codes`、`severity`、`problems[]`。
`problems[]` 是精简数组：`code`（未聚类 `null`）、`label`、`severity`、`component`、`session_level`；
完整定义 / 原因 / 证据走详情。

`trace_id` 不全局唯一（跨模型 / 重跑），详情必须带 `day`；导出按 `(trace_id, day, app_version)` 去重。

## 5. 批量摘要 `POST /traces/batch`

```http
POST /api/v1/analysis/traces/batch
{"dataset":"wencai_eval","trace_ids":["20003020179383635368500000000618"]}
```

最多 1000 个；返回顺序同请求。未知 / 未分析 id 标 `status:"not_analyzed"`。

## 6. 单条详情 `/traces/{trace_id}`

```http
GET /api/v1/analysis/traces/<trace_id>?dataset=wencai_eval&day=2026-11-05
```

- `day` 必填；同一 trace 同日重跑取最新一版。
- 返回摘要字段 + `session`（`2_rsi_input` 整行）+ `trace`（命中的 trace 对象）+
  `analysis.problems[]`（完整 `definition` / `phenomena` / `reason` / `evidence`）。
- `data.file` 是来源归因文件名；`analysis.history[]` 是同 trace 更早的分析行。
- 404 带 `details.reason`：`day_mismatch`（附 `available_days`）、`test_user_excluded`、`not_analyzed`。

## 7. 按用户聚合 `/users`

```http
GET /api/v1/analysis/users?dataset=wencai_eval&severity=P0&sort=severity&limit=50
```

`sort`：`severity`（默认）/ `problems` / `traces` / `recent`。返回每个用户的 `analyzed` 分母、
P0–P4 明细、`first_day` / `last_day`、`sample_trace_id` / `sample_session_id`。
先 `/users?severity=P0` 拿人，再 `/traces?severity=P0&user_ids=<uid>` 拉该用户的 P0 trace。

## 增量同步 `/changes`

不要按时间戳重拉（归因文件会补数 / 重跑 / 整份重写，mtime 不可靠）。用服务端变更序号：

```bash
# 首次：不传 since = 全量导出，按 next_cursor 翻页
curl -s "$WCAPI/changes?dataset=wencai_eval&page_size=500"

# 之后：保存上一轮的 next_since
curl -s "$WCAPI/changes?dataset=wencai_eval&since=<next_since>"
```

- 主键 `(trace_id, day, app_version)`；`items[]` 与 `/traces` 同构，另带
  `change:{seq, op, changed_at}`；`deleted[]` 是删除墓碑。
- 先落库、后更新位点；同一 `since` 重放幂等。位点失效返回 409 `SYNC_RESET`，从空 `since` 重同步。
- 完整说明：`GET /api/v1/analysis/docs/incremental`。

## 跳到 5002 对话详情页

```text
http://<乌兰 5002 对外地址>/?product=wencai&case=daily|b_expert|<session_id>&trace=<trace_id>
```

`case` 里的 `|` 要写成 `%7C`；`session_id`、`trace_id` 都从 `/traces` 条目取。
也可以直接在看板「具体数据」地址栏复制链接，把端口换成页面服务的对外端口。

## 分页、上限与错误

- `cursor` 不透明，绑定筛选条件与页大小；30 分钟过期返回 410 `CURSOR_EXPIRED`。
- `/traces` `page_size` ≤100（`ids_only=true` ≤5000）；`/summary`、`/severity`、`/users`
  `limit` ≤1000；`/changes` `page_size` ≤1000；`user_ids` ≤5000、`trace_ids` ≤1000。
- 未知编码 / 严重度 / `dataset` → 422 `UNKNOWN_VALUE`；超限 → 413 `TOO_MANY_IDS`；
  并发超过 32 → 429 `RATE_LIMITED`（带 `Retry-After`）。
