# 问财 RSI 供数接入说明（v2.0）

只读、无认证查询接口，部署于乌兰察布容器端口 `5003`，前缀 `/api/v1/analysis`，服务单一数据集 `dataset=wencai_eval`。

- **集群内**：`http://interactive-i6piqwvlnsr5:5003/api/v1/analysis`（同容器 `127.0.0.1:5003`）；对外由平台映射 5003 端口。
- **健康检查**：`GET /healthz`；**在线文档**：`GET /api/v1/analysis/docs[/{name}]`。
- **响应包络**：200 统一 `{request_id, schema_version:"2.0", data, meta}`（`meta` 含 `taxonomy_versions`、`data_updated_at`、`built_at`、`latest_seq`、`filters`）；支持 `Accept-Encoding: gzip`。

## 1. 数据来源与口径

数据源位于 `0_wencai/eval_output/2_rsi_eval/<model>/<cohort>/*_attribution-<date>.jsonl`、累计聚类树 `cluster/<model>/total/` 及输入 `eval_input/2_rsi_input/<model>/<cohort>/data_<YYYYMMDD>.jsonl`（无 compact）。

| 维度 | 取值与来源 |
|---|---|
| `app_version` | `b_expert`、`b_fast`（RSI 模型目录名） |
| `source` | 用户分层 cohort：`新用户W1-3`、`新用户W4以上`、`老用户W1-3`、`老用户W4以上` |
| `day` | `YYYY-MM-DD`，按 **`Asia/Shanghai`** 从 `turns[].meta.timestamp` 换算（缺省取批次日） |
| `problem` | 累计聚类树编码（如 `S9.M5.1`）；未聚类 `code=null` 照常计入问题数与 P0–P4，分组落 `"未聚类"` |
| `intent` | 当前 RSI 归因基本无意图字段，通常为 `null`，不要依赖 `intent` 分组 |

- **trace**：单轮对话（`turns[].meta.trace_id`，跨模型/重跑不唯一）；同一 session 多轮各算一条。
- **测试账号不供数**：仅纯 ASCII 数字且 ≤ 10 位为真实用户，其余整条排除（规则同看板 `user_rules.json`）。数据每小时增量刷新。

## 2. 通用筛选参数（`/summary`、`/severity`、`/traces`、`/users` 共用）

| 参数 | 类型 | 说明 |
|---|---|---|
| `dataset` | 必填 | 固定 `wencai_eval`（传 `aime_eval` 返回 422） |
| `source` | 多值 | cohort（如 `新用户W1-3`） |
| `start_day` / `end_day` | `YYYY-MM-DD` | 北京时间日期，闭区间 |
| `problem` | 多值编码 | 传大类自动展开至子孙；未知码返回 422 |
| `severity` | 多值 | `P0`–`P4`（P0 最重，P4 为过程已恢复提示级） |
| `app_version` | 多值 | `b_expert`、`b_fast` |
| `user_ids` / `q` | 多值 / 单值 | `user_ids ≤ 5000`（超限 413）；`q` 问句模糊子串 ≤ 200 字 |

GET 多值逗号分隔，POST 用 JSON 数组；不同参数取「且」，同参数多值取「或」。

## 3. 核心接口

| 端点 | 方法 | 用途与关键返回 |
|---|---|---|
| `/taxonomy` | GET | `kind=problem&app_version=b_expert\|b_fast` 或 `kind=severity` |
| `/severity` | GET/POST | P0–P4 统计：`severity.Pn.{problems,traces}`、`unlabeled`、`analyzed`；`group_by` 可省略 |
| `/summary` | GET/POST | 多维聚合：`group_by`（1–2 维必填：`problem/day/user/app_version/source`）、`level=top\|leaf\|children` |
| `/traces` | GET/POST | 列表（固定 `asked_at DESC, trace_id DESC`）：`page_size ≤ 100`（`ids_only=true` ≤ 5000），含 `source`(cohort)、`session_id`、精简 `problems[]` |
| `/users` | GET/POST | 按用户聚合（`sort=severity\|problems\|traces\|recent`），返回每人 `analyzed`、P0–P4 明细与 `sample_trace_id` |
| `/traces/batch` | POST | 批量摘要（`trace_ids ≤ 1000`），按请求顺序返回；未分析标 `status:"not_analyzed"` |
| `/traces/{id}` | GET | 单条详情（**`day` 必填**）：含 `session`（`2_rsi_input`）、`trace`、`data.file`、完整 `analysis.problems[]` 与 `history[]` |
| `/changes` | GET/POST | 增量同步流：不传 `since` 得全量 + `next_since`，后续传 `since` 只拉 `upsert/delete`，主键 `(trace_id, day, app_version)`，详见 `GET /docs/incremental` |

- `analyzed` 分母 = 去掉 `problem`/`severity` 筛选且忽略 `problem` 分组维度后的 trace 数；按 `problem` 分组时各组 `problems` 之和 = `total.problems`。

## 5. 上限、错误码与自检

- **上限**：`/summary`、`/severity`、`/users` `limit ≤ 1000`；`/changes` `page_size ≤ 1000`；并发上限 32；`cursor` 30 分钟过期（`410 CURSOR_EXPIRED`）。
- **错误码**：`400 INVALID_ARGUMENT`、`404 NOT_FOUND`（`day_mismatch`/`test_user_excluded`/`not_analyzed`）、`409 SYNC_RESET`、`410 CURSOR_EXPIRED`、`413 TOO_MANY_IDS`、`422 UNKNOWN_VALUE`、`429 RATE_LIMITED`、`503 UNAVAILABLE`。
- **只读自检**：`python3 scripts/audit_analysis_api.py http://127.0.0.1:5003`（退出码非 0 即失败）。
