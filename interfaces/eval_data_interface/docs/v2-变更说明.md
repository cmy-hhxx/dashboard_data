# v2 变更说明：从「错误判定」改为「问题条目 + 严重度」

日期：2026-11-03 · 服务：`eval_data_interface`（5003 供数）

## 为什么改

v1 把分析结果压缩成一个 `has_error` 布尔和一组 `error_codes`，语义上暗示“这条 trace 错了”。
但数据里**没有标准答案**（`is_correct` 全为 `null`），分析组产出的是**问题条目**：
每条带 `label`、`severity`（P0–P4）、`component`、`evidence`，其中被聚类流水线覆盖的才有编码。
继续用 `is_error` / `has_error` 表达，会同时犯两个错：

1. 把“发现了问题”说成“答案是错的”；
2. 未聚类问题（有严重度、没有编码）被当成“没问题”。

v2 的真相只有一条：**每条 trace 的 `problems` 数组**。数量、占比、下钻全部由它派生：

- 数严重度 → `GET /severity`（P0–P4 的问题条目数与 trace 数）；
- 看是哪些 trace → `GET /traces?severity=P0`（列表里带 `problems[]`）；
- 按问题编码聚合 → `GET /summary?group_by=problem`（未聚类问题进 `problem: null`）。

## 破坏性变更（schema 1.0 → 2.0）

| v1 | v2 | 说明 |
|---|---|---|
| `error_codes` | `problem_codes` | 仍是已聚类的最细编码、去重排序；未聚类不计入 |
| `has_error` | 删除 | 用 `problems` 是否为空 / `problem_count` 判断 |
| `error_traces` | `problem_traces` | 至少一个问题条目的 trace 数；新增 `problems`（条目数） |
| 筛选参数 `error` | `problem` | 语义不变：命中任一编码或其子孙 |
| 筛选参数 `has_error` | 删除 | 用 `severity=P0,P1,P2,P3,P4` 或 `problem` 筛选 |
| `group_by=error` | `group_by=problem` | 未聚类问题进 `null` 组 |
| `/taxonomy?kind=error` | `kind=problem` | 节点不再有 `counts_as_error`（恒 true 的假开关） |
| （无） | `session_id` | trace 条目新带会话 ID，用于拼样本详情页链接 |
| （无） | `/severity` | 新增：按筛选条件数 P0–P4 的问题条目数与 trace 数 |
| （无） | `/taxonomy?kind=severity` | 新增：P0–P4 的定义与顺序 |
| `correct_reason` | 删除 | 数据里没有可填内容 |
| `is_correct` | 保留 | `true` / `false` / `null`；当前恒 `null`，不做筛选与统计 |

版本号：`schema_version` 由 `1.0` 升为 `2.0`。接口前缀仍是 `/api/v1/analysis`（v1 没有外部接入方，
不保留双轨）。

## 计数口径

- **问题条目数**：`problems`，一个 trace 可贡献多条。
- **trace 数**：`problem_traces`（至少一条问题的 trace）/ `severity.Pn.traces`
  （至少一条该等级问题的 trace）。
- 问题条目数 = Σ P0–P4 条目数 + `unlabeled`（严重度缺失，当前为 0）。
- 一条 trace 可同时有多个等级，各等级 `traces` 之和可以大于 `traces`。
- 未聚类问题、session 级问题（`session_level: true`）都计入，严重度直接从条目上取，不依赖编码。
- 按 `problem` 编码分组时，每个问题条目只归一个组：`traces` 可跨组重复计，`problems` 各组之和
  等于总条目数；未聚类问题进 `null` 组；没有问题的 trace 不进入 problem 分组。

## 严重度定义

与看板体系页一致（P0 最重 → P4 最轻）：

| code | definition |
|---|---|
| P0 | 确认有剩余影响，程度最重 |
| P1 | 确认有剩余影响 |
| P2 | 确认有剩余影响 |
| P3 | 确认有剩余影响，程度最轻 |
| P4 | 过程缺陷已恢复，未进入交付 |
