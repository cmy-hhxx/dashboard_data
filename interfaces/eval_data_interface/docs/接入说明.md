# 接入说明（给 RSI 看板）

服务：`eval_data_interface`，对话分析查询接口 v1.0 的实现。只读，无认证。

| 方向 | 地址 |
|---|---|
| 对内 | `http://interactive-i6piqwvlnsr5:5003/api/v1/analysis` |
| 对外 | `http://117.50.195.94:3335/api/v1/analysis` |
| 健康检查 | `GET /healthz`（返回 `ok` / `building` / `traces` / `data_updated_at`） |

请求头：`Accept: application/json`；POST 另带 `Content-Type: application/json`。
所有 200 响应统一为 `{request_id, schema_version, data, meta}`，`meta` 里有
`taxonomy_version`、`taxonomy_versions`、`data_updated_at`、`filters`（实际生效的筛选条件回显）。

## 与协议的 4 处差异（先看这里）

1. `dataset` 只有一个取值 **`aime_eval`**（本服务只服务 AIME）。传 `daily` / `overseas` 会 422。
2. `GET /taxonomy?kind=error` 需要 **`app_version`** 选树（有两棵树）：
   `AIME-Atlas_expert`（196 节点）、`aime-fast-new_fast`（142 节点），版本都是 `4.1.3`。
   `kind=intent` 不需要 `app_version`，版本 `2026-10`。
3. `GET /traces/{trace_id}` 返回的是 **`eval_input` 的完整结构体**（`session` 整行 + `trace` 对象）
   加一个 `analysis` 块，而不是协议里的 `query` / `final_output` / `steps` 三件套。
4. 只有被聚类过的问题才有编码。未被聚类的问题（约 20% 的 trace）不会出现在 `error_codes` 里，
   `has_error` 也是 `false`——它们看起来就是“没有问题”。

## 通用筛选参数

`/summary` 与 `/traces` 共用：`dataset`（必填，`aime_eval`）、`source`（`prelaunch`/`feedback`）、
`start_day`/`end_day`、`intent`、`error`、`has_error`、`app_version`、`user_ids`、
`taxonomy_version`、`q`（仅 `/traces`）。

- GET 多值用英文逗号，POST 用 JSON 数组；空字符串视为未提供。
- 不同参数之间是「且」，同参数多值之间是「或」。
- 传大类编码（`T01`、`S9`、`S9.M5`）会自动展开到全部子孙。
- 未知编码 → 422 `UNKNOWN_CODE`（`details.unknown` 列出未知值）；`user_ids` 超过 5000 → 413。

## 1. 分类树

```http
GET /api/v1/analysis/taxonomy?kind=intent
GET /api/v1/analysis/taxonomy?kind=error&app_version=AIME-Atlas_expert
```

`data.nodes[]` 每项：`code`、`label`、`parent_code`、`level`、`order`、`definition`、`counts_as_error`。
`data.versions[]` 是版本列表（当前只有一条，`status=current`）。

- 意图：`T01`（事件解读）→ `T01.S02`（行情事件解读）…… 27 个顶层、169 个子类。
- 问题：`S9`（答案合成）→ `S9.M5`（加工计算错误）→ `S9.M5.1`（旧数据当当前值）……
- `counts_as_error` 恒为 `true`（P4 也计入错误）。

## 2. 聚合

```http
GET /api/v1/analysis/summary?dataset=aime_eval&group_by=intent
POST /api/v1/analysis/summary
{"dataset":"aime_eval","group_by":["intent","error"],"app_version":["AIME-Atlas_expert"],"user_ids":["u1","u2"]}
```

参数：`group_by`（1–2 个：`intent`、`error`、`day`、`user`、`app_version`、`source`）、
`level`（`top`/`leaf`/`children`）、`sort`（`traces`/`users`/`rate`）、`limit`（默认 100，最大 1000）、
`cursor`。

```json
{
  "data": {
    "total": {"analyzed": 10578, "traces": 8421, "users": 3211, "error_traces": 6543},
    "groups": [
      {"keys": {"intent": "T01"}, "analyzed": 1683, "traces": 1683, "users": 901, "error_traces": 1120}
    ],
    "next_cursor": null,
    "has_more": false
  }
}
```

- `analyzed` 是分母：去掉 `error`/`has_error` 并忽略分组键里的 `error` 维度后的 trace 数。
- 按 `error` 分组时一条 trace 可落在多个组，各组之和可能大于 `total.traces`。
- 未分出意图的 trace 进 `{"intent": null}` 组。

## 3. trace 列表

```http
GET /api/v1/analysis/traces?dataset=aime_eval&intent=T01&page_size=20
```

参数：通用筛选 + `page_size`（默认 20，最大 100；`ids_only=true` 时最大 5000）、
`cursor`、`ids_only`。排序固定 `(asked_at DESC, trace_id DESC)`。

`items[]`：`trace_id`、`day`、`asked_at`（UTC）、`source`、`user_id`、`app_version`、
`query_preview`（≤160 字）、`intent_code`、`error_codes`（最细一级）、`has_error`、
`analysis_id`、`analyzed_at`。

`total` 是当前筛选下的准确总数，恒等于 `/summary` 对应分组的 `traces`。

## 4. 批量取摘要

```http
POST /api/v1/analysis/traces/batch
{"dataset": "aime_eval", "trace_ids": ["trace_a", "trace_b"]}
```

最多 1000 个 id，返回顺序与请求一致，每个 id 一条；不认识的 id 标 `status: "not_analyzed"`，
分析字段为 `null`、`error_codes` 为 `[]`。

## 5. 单条详情

```http
GET /api/v1/analysis/traces/{trace_id}?dataset=aime_eval&day=2026-10-23
```

`day` **必填**（`trace_id` 只在单日内唯一，且同一天可能有重跑的多行，取最新一版）。

```json
{
  "data": {
    "trace_id": "d4806fd56d6a4f9abf9a983aeb36b5d5",
    "day": "2026-10-23", "source": "prelaunch", "user_id": "xutianhao",
    "app_version": "AIME-Atlas_expert", "intent_code": "T01.S02",
    "error_codes": ["S9.M5.1"], "has_error": true,
    "analysis_id": "an_…", "analyzed_at": "2026-11-02T…Z",
    "session": { "…eval_input 整行：meta、traces、case_id、version…" },
    "trace": { "meta": {...}, "messages": [...], "message_pool": [...], "tool_sets": [...] },
    "analysis": {
      "intent": {"task": "事件解读", "subtask": "行情事件解读", "code": "T01.S02"},
      "summary": "轮次摘要",
      "problems": [
        {"code": "S9.M5.1", "label": "旧数据当当前值", "severity": "P2",
         "definition": "…", "reason": "…", "component": "answer_synthesis",
         "evidence": [{"position": "trace_index 0 / message_index 16 / path /content", "quote": "…"}]}
      ],
      "history": [
        {"analysis_id": "an_…", "analyzed_at": "2026-11-01T…Z", "intent_code": "T01.S02",
         "error_codes": ["S1.M1.1"], "file": "…jsonl", "line": 7}
      ]
    }
  }
}
```

- `session` / `trace` 直接来自 `eval_input`，结构与轨迹接口一致，可整块渲染。
- `analysis.problems[].code` 来自聚类 `item_index`；未聚类的问题 `code` 为 `null`，但 `label` 仍在。
- `history` 是同一天里同一 trace 更早的分析行（重跑）。
- trace 不存在或未分析 → 404。

## 分页与 cursor

`cursor` 是不透明字符串，绑定首次请求的筛选条件、`group_by`、`sort`、`page_size`；
30 分钟内有效，过期返回 410 `CURSOR_EXPIRED`（从第一页重来）。
翻页期间新增的分析结果可能不出现，但已有记录不会重复或遗漏。

## 错误

| HTTP | code | 场景 |
|---|---|---|
| 400 | `INVALID_ARGUMENT` | 参数格式错、`group_by` 为空/超过 2 个、`level=children` 未恰好筛一个编码、`start_day > end_day`、缺 `day` |
| 404 | `NOT_FOUND` | trace 不存在或未分析、分类版本不存在 |
| 410 | `CURSOR_EXPIRED` | cursor 过期 |
| 413 | `TOO_MANY_IDS` | `user_ids` > 5000、`trace_ids` > 1000 |
| 422 | `UNKNOWN_CODE` | 未知编码或枚举值 |
| 503 | `UNAVAILABLE` | 索引还在构建（看 `/healthz` 的 `building`） |

## 数据新鲜度

`meta.data_updated_at` 是最新一批分析结果的更新时间；服务每 30 分钟增量重建索引。
页面上的“数据截至”用这个字段。
