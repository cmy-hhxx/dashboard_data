# AIME 对话分析供数接入说明（v2.0）

只读、无认证查询接口，直接返回 trace 问题条目与 P0–P4 严重度（无标准答案，`is_correct` 恒 `null`）。

- **对外地址**：`http://10.217.219.2:2477/api/v1/analysis`
- **集群内**：`http://interactive-s3ynzadcvm9c:5003/api/v1/analysis`（同容器 `127.0.0.1:5003`）
- **健康检查**：`GET /healthz`；**在线文档**：`GET /api/v1/analysis/docs[/{name}]`
- **响应包络**：200 统一 `{request_id, schema_version:"2.0", data, meta}`（`meta` 含 `taxonomy_versions`、`data_updated_at`、`built_at`、`latest_seq`、`filters`）；错误为 `{request_id, error:{code, message, details}}`。支持 `Accept-Encoding: gzip`。

## 1. 核心概念与口径

- **trace**：单轮对话，`trace_id` 取 `turns[].meta.trace_id`（跨模型/重跑不唯一）；同一 session 多轮各算一条。
- **problem & severity**：`P0`–`P3` 为确认有剩余影响（P0 最重），`P4` 为过程缺陷已恢复未进入交付；不是对错判定。
- **problem code**：聚类树编码（如 `S9.M5.1`）；`code=null` 表示**未聚类**（非“其他”或故障），照常计入问题数与 P0–P4，按 `problem` 分组落 `{"problem": null, "problem_label": "未聚类"}`。旧编码保留于 `legacy_code`，展示优先用 `current_code` / `problem_label`。
- **intent**：金融意图分类体系 v1.9（`2026-11`，`FIN-L1-01`–`FIN-L1-19` / `FIN-L2-001`–`FIN-L2-123`）；老体系标签 `intent_code=null`。
- **`day` 时区**：按 `meta.timestamp` 换算美东时间（`America/New_York`），非批次文件名日期。数据每小时增量刷新。
- **测试账号不供数**：仅纯 ASCII 数字且 ≤ 10 位为真实用户，其余整条 trace 不进入任何接口（详情返回 404 `test_user_excluded`）。

## 2. 通用筛选参数（`/summary`、`/severity`、`/traces`、`/users` 共用）

| 参数 | 类型 | 说明 |
|---|---|---|
| `dataset` | 必填 | 固定 `aime_eval`（其它值返回 422） |
| `source` | 多值 | `prelaunch`（日常）/ `feedback`（流失） |
| `start_day` / `end_day` | `YYYY-MM-DD` | 美东日期，闭区间 |
| `intent` / `problem` | 多值编码 | 传大类自动展开至子孙；旧编码按最近祖先解释；未知码返回 422 |
| `severity` | 多值 | `P0`–`P4`（至少命中一个该等级问题） |
| `app_version` | 多值 | `AIME-Atlas_expert`、`aime-fast-new_fast` 等 |
| `user_ids` / `q` | 多值 / 单值 | `user_ids` ≤ 5000（超限 413）；`q` 问句模糊子串 ≤ 200 字 |

GET 多值逗号分隔，POST 用 JSON 数组；不同参数取「且」，同参数多值取「或」。

## 3. 核心接口

| 端点 | 方法 | 用途与关键返回 |
|---|---|---|
| `/taxonomy` | GET | `kind=intent\|problem\|severity`（`problem` 需传 `app_version`）；返回 `nodes[]` |
| `/severity` | GET/POST | P0–P4 统计：`severity.Pn.{problems,traces}`、`unlabeled`、`analyzed`；`group_by`（0–2 维，可省略） |
| `/summary` | GET/POST | 多维聚合：`group_by`（1–2 维必填：`intent/problem/day/user/app_version/source`）、`level=top\|leaf\|children`；返回 `analyzed`/`traces`/`users`/`problem_traces`/`problems` |
| `/traces` | GET/POST | 列表（固定 `asked_at DESC, trace_id DESC`）：`page_size ≤ 100`（`ids_only=true` ≤ 5000）；每条含 `session_id`、`intent_code`、`task`/`subtask`、`severity` 计数与精简 `problems[]` |
| `/users` | GET/POST | 按用户聚合（如 `/users?severity=P0`）：`sort=severity\|problems\|traces\|recent`，返回每人 `analyzed`、P0–P4 明细与 `sample_trace_id` |
| `/traces/batch` | POST | 批量摘要（`trace_ids ≤ 1000`），按请求顺序返回；未分析标 `status:"not_analyzed"` |
| `/traces/{id}` | GET | 单条详情（**`day` 必填**）：含完整 `session`、`trace`、`data.file`、`analysis.problems[]`（含 `definition/phenomena/reason/evidence`）与 `history[]` |
| `/changes` | GET/POST | 增量同步流（推荐替代全量导出）：不传 `since` 得全量 + `next_since`，后续传 `since` 只拉 `upsert/delete`，按 `(trace_id, day, app_version)` 落库，详见 `GET /docs/incremental` |

- `analyzed` 分母 = 去掉 `problem`/`severity` 筛选且忽略 `problem` 分组维度后的 trace 数。
- 按 `problem` 分组时每个条目只归一组（`Σgroups.problems == total.problems`），同一 trace 可跨组重复计数。

## 5. 上限与错误码

- **上限**：`/summary`、`/severity`、`/users` `limit ≤ 1000`；`/changes` `page_size ≤ 1000`；`group_by ≤ 2`；并发上限 32；`cursor` 有效期 30 分钟。
- **错误码**：`400 INVALID_ARGUMENT`（参数非法/缺 `day`/缺 `group_by`）、`404 NOT_FOUND`（`details.reason`: `day_mismatch`/`test_user_excluded`/`not_analyzed`）、`409 SYNC_RESET`（位点失效需全量重同步）、`410 CURSOR_EXPIRED`、`413 TOO_MANY_IDS`、`422 UNKNOWN_CODE`、`429 RATE_LIMITED`（见 `Retry-After`）、`503 UNAVAILABLE`（首轮构建中）。
